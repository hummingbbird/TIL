## 문제 설명

도둑 A와 도둑 B가 여러 개의 물건을 훔치려고 합니다. 각 물건을 훔칠 때 도둑 A가 남기는 흔적의 정도와 도둑 B가 남기는 흔적의 정도가 주어집니다.

* **제약 조건**:
* 도둑 A가 남긴 흔적의 총합이 **$n$ 이상**이 되면 경찰에 붙잡힙니다.
* 도둑 B가 남긴 흔적의 총합이 **$m$ 이상**이 되면 경찰에 붙잡힙니다.
* 두 도둑 모두 붙잡히지 않아야 하며, 물건을 모두 훔쳤을 때 **도둑 A가 남긴 흔적의 최솟값**을 구해야 합니다.
* 만약 어떤 방법으로도 경찰에 붙잡히지 않고 모든 물건을 훔칠 수 없다면 `-1`을 리턴합니다.



### 제한사항

* `info`는 각 물건을 훔칠 때 A와 B가 남기는 흔적을 담은 2차원 배열이며, 세로 길이(물건의 개수)는 `1` 이상 `50` 이하입니다.
* `info`의 각 원소는 `[A가 남기는 흔적, B가 남기는 흔적]` 형태이며, 각 원소의 값은 `1` 이상 `120` 이하입니다.
* `n`은 도둑 A의 경찰 체포 기준 흔적 누적치이며, `1` 이상 `120` 이하입니다.
* `m`은 도둑 B의 경찰 체포 기준 흔적 누적치이며, `1` 이상 `120` 이하입니다.

## 입출력 예

| info | n | m | return |
| --- | --- | --- | --- |
| `[[1, 2], [2, 3], [2, 1]]` | 10 | 9 | `2` |
| `[[1, 2], [2, 3], [2, 1]]` | 4 | 4 | `-1` |

# 💡 접근 방법 및 풀이 과정

## 1. 처음 내 접근 방식

```
    # a도둑이 물건 2를 훔치면 info[i][0], n이상이면 잡힘
    # b도둑이 물건 2를 훔치면 info[i][1], m이상이면 잡힘
    # 물건 모두 훔쳤을 때 a 흔적의 최솟값, 없으면 -1 return
    
    # 1번을 a가 훔쳤/b가 훔쳤 -> 2를 a가훔쳤/b가훔쳤 이렇게 모든 경우의 수를 가지치기해서 쭉 가봐..
    # 다 돌면 종료, n혹은 m을 넘치면 그만! -1 return
    # dp는 이전 것중에 어떤 기준으로 최소 최대 이런 식으로 고를 수가 있어야 되는데 이건 그게 되나? 
    # 각 물건 별로(i) a, b의 흔적 중 작은 걸로 라는 게 말이 안 되는데.. 

    # i=0 -> 1,0 / 0, 2 -> 가능진출조합 = [[1,0], [0,2]]
    # i=1 -> 3,0 / 1,3 / 2,2 / 2, 5 -> 가능진출조합 = [[3,0], [1,3], [2,2]]
    # i=2 ->  ... 이런 식으로 하면 됨.
```

수확은 1. 쭉 돌아야 한다는 점을 파악한 것 2. 예제를 통해 전체 흐름을 구상해내고 그것을 구현해낸 것.

그리하여 만들어낸 코드는 아래와 같다.

```python
def solution(info, n, m):
    
    if n == 1:
        if sum(map(lambda x:x[1], info)) >= m:
            return -1
        else:
            return 0
    
    elif m == 1:
        if sum(map(lambda x:x[0], info)) >= n:
            return -1
        else:
            return sum(map(lambda x:x[0], info))
    queue = [[info[0][0],0], [0, info[0][1]]]
    
    for i in range(1, len(info)):
        hubo = []
        for q in queue:
            a, b = q
            if a+info[i][0] < n:
                hubo.append([a+info[i][0], b])
            if b+info[i][1] < m:
                hubo.append([a, b+info[i][1]])
        queue = hubo
    
    # 정렬 후 리턴
    queue.sort(key=lambda x:x[0])
    return queue[0][0]

```

## 2. queue 써보기

시간초과가 나니까 .. 그냥 괜히 queue 써봤다. 사실 지금 생각해보면 이정도 차이로 난 시간초과가 아니었음. 단순히 자료 구조의 문제가 아닌 .. 애초에 전체를 순회함으로써 폭발적으로 늘어난 횟수가 원인이었으니 이 방법이 해결책이 될 수 없었던 건 어쩌면 당연한 일. 🤧🤧

암튼 bfs의 구조를 차용해서 풀었다. 왜그랬지? 요 구조를 도입해서 풀면서 '어 이거 뭔가 이전 결과를 기억해야 할 것 같은데, 그렇다면 dp를 쓸 수도 있겠는데'라는 생각을 했다. 

```python
from collections import deque

def solution(info, n, m):
    info_len = len(info)
    if n == 1:
        if sum(map(lambda x:x[1], info)) >= m:
            return -1
        else:
            return 0
    
    elif m == 1:
        if sum(map(lambda x:x[0], info)) >= n:
            return -1
        else:
            return sum(map(lambda x:x[0], info))
    queue = deque([(info[0][0],0,0), (0, info[0][1], 0)])
    
    answer = -1
    while queue:
        a, b, idx = queue.popleft()
        answer = a
        if idx + 1 < info_len and info[idx+1][0]+a < n:
            queue.append((info[idx+1][0]+a, b, idx+1))
        elif idx + 1 < info_len and info[idx+1][1]+b < m:
            queue.append((a, info[idx+1][1]+b, idx+1))
    return answer

```

예제는 맞았지만 당연히 틀렸은. 이건 a,0 아니면 0,b처럼 상호 배타적인 흐름.. 그리디로는 해결할 수 없슨.

그리하여 결국 dp를 사용해 풀었음. 지피티와 함께 .. (gg쳤다고 한 이유)

dp의 용도는 key=a, value=b해서 a일 때 b의 최솟값을 저장하는 용도. 예를 들어 (2,0)일 때 시도했으면 (2, 4)일 때는 시도할 필요가 없는 거임. 그건 어차피 (2, 0) 때보다 worse하니까!

# 💡 그래서 답은

```python
def solution(info, n, m):
    # dp 딕셔너리: { a_sum (도둑 A의 누적 흔적): b_sum (도둑 B의 누적 흔적 최솟값) }
    dp = {}
    
    # 1. 첫 번째 물건 처리
    first_a, first_b = info[0]
    
    # 첫 물건을 A가 훔치는 경우
    if first_a < n:
        dp[first_a] = 0
    
    # 첫 물건을 B가 훔치는 경우
    if first_b < m:
        if 0 in dp:
            dp[0] = min(dp[0], first_b)
        else:
            dp[0] = first_b
            
    # 첫 물건부터 둘 다 한계치를 넘으면 불가능
    if not dp:
        return -1
        
    # 2. 두 번째 물건부터 끝까지 반복
    for i in range(1, len(info)):
        item_a, item_b = info[i]
        next_dp = {}
        
        for a_sum, b_sum in dp.items():
            # [경우 1] 이번 물건을 A에게 주는 경우
            if a_sum + item_a < n:
                next_a = a_sum + item_a
                next_b = b_sum
                # 1. 다음 dp에 next_a가 없거나 2. 이미 있는데 그 값보다 next_b가 작은 경우 -> next에 추가
                if next_a not in next_dp or next_dp[next_a] > next_b:
                    next_dp[next_a] = next_b
                    
            # [경우 2] 이번 물건을 B에게 주는 경우(동일)
            if b_sum + item_b < m:
                next_a = a_sum
                next_b = b_sum + item_b
                if next_a not in next_dp or next_dp[next_a] > next_b:
                    next_dp[next_a] = next_b
        # dp 갱신            
        dp = next_dp
        # 만약 갈 수 있는 유효한 상태가 하나도 없다면 종료
        if not dp:
            return -1
            
    # 3. dp의 a_sum(key) 중 최솟값 반환
    return min(dp.keys()) if dp else -1

```
